Four compose files describe the demonstration environment served under `openfsp.org`. Each one is deployed as its own
[Coolify](https://coolify.io) service and reaches the others over their public addresses only:

- [`gateway/compose.yaml`](gateway/compose.yaml): the gateway and its console.
- [`simulator/compose.yaml`](simulator/compose.yaml): the simulator of the MonCash, NatCash and OpenFSP operators and its
  interface.
- [`validator/compose.yaml`](validator/compose.yaml): the conformance validator and its interface.
- [`demo/compose.yaml`](demo/compose.yaml): the demonstration shop of [openfspht/demo](https://github.com/openfspht/demo).

The first three run the images of [openfspht/openfsp](https://github.com/openfspht/openfsp). The gateway serves the `test`
environment and reaches simulated payment services only.

## Services

| Service | Stack | Address |
|---|---|---|
| `shop` | `demo` | https://demo.openfsp.org |
| `gateway` | `gateway` | https://gateway.openfsp.org |
| `console` | `gateway` | https://console.openfsp.org |
| `postgres` | `gateway` | internal |
| `simulator` | `simulator` | https://simulator-api.openfsp.org |
| `simulator-ui` | `simulator` | https://simulator.openfsp.org |
| `validator-ui` | `validator` | https://validator.openfsp.org |
| `validator` | `validator` | internal |
| `postgres` | `validator` | internal |

Coolify maps each address to its service. The addresses are `A` records of the `openfsp.org` zone.

## Variables

These values are set on the Coolify services and never committed. Every one of them is required.

| Variable | Stack | Content |
|---|---|---|
| `SERVICE_PASSWORD_POSTGRES` | `gateway`, `validator` | Database password, generated by Coolify |
| `OPENFSP_APP_KEY` | `gateway` | Application key, `openssl rand -base64 32`, kept stable: replacing it signs out administrators, makes the stored merchant credentials unreadable and invalidates the callback URLs of pending payments |
| `OPENFSP_ADMIN_TOKEN` | `gateway` | Argon2id hash of the console token, produced by the gateway `hash` command |
| `OPENFSP_DEMO_API_KEY` | `gateway`, `demo` | `ofsp_test_` key registered by the gateway at startup and used by the shop |
| `OPENFSP_VALIDATOR_ATTESTATION_SIGNING_KEY` | `validator` | Ed25519 private key in PKCS#8 PEM that signs the attestations, `openssl genpkey -algorithm ed25519`, mounted as a file |
| `SENTRY_DSN_BACKEND`, `SENTRY_DSN_FRONTEND` | `gateway`, `simulator`, `validator` | Sentry DSN of the services and of their interfaces |
| `SENTRY_DSN_DEMO` | `demo` | Sentry DSN of the shop |

The gateway serves the `test` environment without development mode: HTTPS only, behind the Coolify proxy, with a
`Secure` admin cookie. The validator runs without development mode: it refuses private targets and signs with the
mounted key only. Configuring that key retires the key generated in development mode.

## Deployment order

1. Set `OPENFSP_APP_KEY` and `OPENFSP_VALIDATOR_ATTESTATION_SIGNING_KEY` on their Coolify stacks.
2. Push this repository, then redeploy the `gateway` and `validator` stacks.
3. Push [openfspht/openfsp](https://github.com/openfspht/openfsp).
4. Merge its release pull request.
5. Move the compose files to the new image version and push.

## Update

Every stack runs a pinned release of the images published on Docker Hub. Coolify deploys each one from this repository
on push: a new release reaches production when its version replaces the current one in the compose files, through a
Dependabot pull request or by hand, and rolling back means restoring the previous version.
